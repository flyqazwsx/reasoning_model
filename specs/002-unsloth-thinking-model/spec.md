# Feature Specification: 本機 Thinking Model QLoRA 微調示範 Web 應用程式

**Feature Branch**: `002-unsloth-thinking-model`  
**Created**: 2026-10-09  
**Status**: Draft  
**Input**: User description: "示範一個 unsloth thinking model 的微調，12GB VRAM（3080 Ti）、Ubuntu、Gradio Web App、QLoRA、uv/venv 隔離；介面：自動下載模型與資料集、未微調推論、訓練進度、微調模型登錄後解鎖推論、自動挑選適合硬體的 Hugging Face 模型；依 PRD.md"

## Clarifications

### Session 2026-10-09

- Q: 推薦模型清單的來源？ → A: 固定內建清單（專案預先定義已驗證的 7B–8B 蒸餾推理模型，依顯示卡記憶體篩選）
- Q: 如何判定微調後答對率提升？ → A: 預設並排對照，另提供選配的「執行題庫評測」按鈕（自動比對標準答案，可略過）
- Q: 訓練使用的資料筆數如何決定？ → A: 使用者可自訂「使用筆數」，預設 2,000，範圍 100 至資料集上限
- Q: 多個微調模型是否可管理？ → A: 可刪除（需確認），名稱自動以時間產生，不提供改名
- Q: 需授權才能下載的模型或資料集如何處理？ → A: 不支援；僅公開可下載項目，遇到時顯示說明，不提供權杖輸入介面

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自動挑選並下載適合硬體的模型與資料集 (Priority: P1)

使用者不想自己找模型、資料夾或手動下載。開啟網頁後，系統偵測本機顯示卡的可用記憶體，推薦「在 12GB 顯示卡上能順利訓練」的 thinking／reasoning 基底模型與資料集清單，使用者只要選取並按下載，系統即自動下載並存放到固定的本機資料夾。

**Why this priority**: 沒有模型與資料集，後續推論與訓練都無法進行；且「不要自己下載、自動找適合我硬體的模型」是使用者最明確的需求，也是整個示範的入口。

**Independent Test**: 啟動網頁，確認顯示偵測到的顯示卡與記憶體；選一個推薦模型與一個推薦資料集並下載；完成後確認畫面顯示「已就緒」與資料集樣本數，且重新啟動後不需重新下載。

**Acceptance Scenarios**:

1. **Given** 應用程式剛啟動，**When** 使用者開啟準備頁，**Then** 畫面顯示偵測到的顯示卡名稱與可用記憶體，並只列出預估能在該記憶體內訓練的推薦模型（標示預估記憶體用量），超出者不列出或標示為不建議
2. **Given** 使用者選了一個推薦模型，**When** 按下「下載模型」，**Then** 畫面持續顯示下載進度與日誌，完成後顯示「模型已就緒」
3. **Given** 使用者選了一個推薦資料集，**When** 按下「下載資料集」，**Then** 完成後顯示樣本數與欄位摘要
4. **Given** 模型與資料集已下載過，**When** 使用者重新啟動應用程式並再次選取，**Then** 系統直接使用本機已有的檔案，不重新下載
5. **Given** 使用者手動輸入自訂的模型或資料集代號，**When** 該模型預估超出可用記憶體，**Then** 系統顯示警告與較小的替代建議，並允許使用者自行決定是否繼續
6. **Given** 下載過程中網路中斷，**When** 下載失敗，**Then** 系統顯示清楚的錯誤訊息並提供重試，已下載的部分不遺失
7. **Given** 下載進行中，**When** 使用者按下「取消下載」，**Then** 系統停止下載並顯示「已取消」，已下載的部分保留，之後可重新下載並續傳

---

### User Story 2 - 以未微調模型進行推論 (Priority: P2)

使用者想先看到「還沒微調」的基底模型對同一個問題的回答，作為之後比較的基準。

**Why this priority**: 這是展示微調效果的「Before」，且不需訓練即可獨立使用與驗證，能最早帶來可見價值。

**Independent Test**: 只完成模型下載後，輸入一個推理題，調整生成參數並執行，確認畫面顯示完整回答（含思考過程），且過程中記憶體未超出上限。

**Acceptance Scenarios**:

1. **Given** 基底模型已就緒，**When** 使用者輸入問題並按下推論，**Then** 畫面顯示模型回答，其中思考過程與最終答案可分辨
2. **Given** 使用者調整最大輸出長度、溫度等生成參數，**When** 執行推論，**Then** 參數確實影響結果（例如最大長度限制了輸出長度）
3. **Given** 尚未下載任何模型，**When** 使用者進入推論頁，**Then** 推論按鈕不可用，並提示先到準備頁下載模型
4. **Given** 推論進行中，**When** 回答逐步產生，**Then** 畫面以串流方式逐步顯示，不需等到全部完成

---

### User Story 3 - QLoRA 訓練並即時看到進度 (Priority: P3)

使用者在模型與資料集就緒後，設定少量參數（訓練回合數、學習率、LoRA 設定），按下開始訓練，並在過程中持續看到進度、損失值變化與日誌。

**Why this priority**: 這是專案核心「微調」動作，但必須建立在 P1、P2 之上，且是產生 P4 微調模型的前提。

**Independent Test**: 在模型與資料集就緒後，使用小樣本資料集啟動訓練；確認進度條與日誌連續更新、損失值被記錄，並能在完成後得到可重複載入的微調成果。

**Acceptance Scenarios**:

1. **Given** 模型與資料集已就緒，**When** 使用者採用預設參數按下「開始訓練」，**Then** 畫面顯示目前回合、步數百分比、損失值與預估剩餘時間，並持續更新
2. **Given** 訓練進行中，**When** 日誌產生新內容，**Then** 日誌框即時追加，且完整日誌同時存成本機檔案可事後回放
3. **Given** 訓練進行中，**When** 使用者查看其他功能，**Then** 下載與模型選擇按鈕暫時鎖定，避免互相干擾
4. **Given** 訓練進行中，**When** 使用者按下終止，**Then** 系統先顯示警告確認，確認後安全停止並保留已完成的檢查點
5. **Given** 訓練過程記憶體不足，**When** 發生失敗，**Then** 畫面顯示明確原因與建議調整項（如降低序列長度或批次設定），並保留日誌
6. **Given** 訓練中途被意外中斷，**When** 使用者重新啟動並選擇繼續，**Then** 系統從最近的檢查點接續，而非從頭開始

---

### User Story 4 - 微調模型自動登錄並解鎖推論、前後對照 (Priority: P4)

訓練完成後，系統自動把新產生的微調模型加入下拉選單，原本灰色的「用微調模型推論」按鈕變為可用，使用者可用同一個問題比較微調前後的回答。

**Why this priority**: 這是整個示範的結果呈現（After 與前後對照），回答使用者「如何展現結果」的問題。

**Independent Test**: 完成一次訓練後，確認下拉選單出現新模型、按鈕由灰變亮；輸入與 P2 相同的問題，確認可得到微調後的回答並與基準並排比較。

**Acceptance Scenarios**:

1. **Given** 尚未有任何微調模型，**When** 使用者進入微調推論區，**Then** 「用微調模型推論」按鈕為灰色不可按，並說明需先完成訓練
2. **Given** 一次訓練成功完成，**When** 完成訊息出現，**Then** 微調模型下拉選單自動出現新項目（含建立時間與基底模型資訊），且按鈕變為可用
3. **Given** 使用者選取微調模型並輸入問題，**When** 按下推論，**Then** 畫面顯示該微調模型的回答
4. **Given** 同一個問題，**When** 使用者要求對照，**Then** 畫面並排顯示「微調前」與「微調後」的回答
5. **Given** 應用程式重新啟動，**When** 使用者回到畫面，**Then** 先前訓練出的微調模型仍在下拉選單中，按鈕維持可用
6. **Given** 訓練失敗或被終止且沒有成品，**When** 使用者查看選單，**Then** 不會出現無法使用的項目，按鈕維持灰色

---

### Edge Cases

- 顯示卡記憶體低於 12GB 或偵測不到顯示卡時，系統如何提示？（顯示明確警告，僅提供最小模型或說明無法訓練）
- 磁碟剩餘空間不足以放下模型或資料集時？（下載前檢查並提示所需空間）
- 資料集欄位格式不被支援，或缺少思考過程欄位時？（顯示驗證結果與無法使用的原因，不開始訓練）
- 使用者刪除正在被推論使用的微調模型？（推論進行中禁止刪除並提示）
- 同一時間使用者重複按下載或開始訓練？（忽略重複請求並提示進行中）
- 訓練與推論同時搶用顯示記憶體？（訓練期間禁止推論，並說明原因）
- 使用者輸入的模型代號不存在或需要授權才能下載？（顯示友善錯誤並提示可能原因）
- 訓練出的微調成果檔案被手動刪除，但登錄資訊仍在？（啟動時偵測並從選單移除失效項目）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在啟動時偵測顯示卡名稱與可用記憶體，並顯示於畫面
- **FR-002**: 系統 MUST 依偵測到的可用記憶體，自動篩選並推薦適合本機訓練的 thinking／reasoning 基底模型，並標示每個模型的預估記憶體用量
- **FR-003**: 系統 MUST 提供推薦資料集清單，且資料集包含思考／推理過程的內容
- **FR-004**: 使用者 MUST 能選取推薦項目或手動輸入模型與資料集代號，系統自動下載並存放到固定的本機資料夾，使用者不需自行下載或指定資料夾
- **FR-005**: 系統 MUST 在下載期間顯示進度與日誌；已下載的內容 MUST 在重新啟動後直接重用，不重複下載；使用者 MUST 能在下載途中取消，已下載的部分保留以便續傳
- **FR-006**: 系統 MUST 在資料集下載後顯示樣本數與欄位摘要，並驗證其是否可用於訓練
- **FR-007**: 使用者 MUST 能以未微調的基底模型進行推論，並調整最大輸出長度、溫度、取樣範圍等生成參數；輸出以串流方式顯示
- **FR-008**: 系統 MUST 在輸出中讓使用者分辨「思考過程」與「最終答案」；若模型輸出不含思考標記，則整段輸出視為最終答案，思考區顯示「此模型未輸出思考過程」
- **FR-009**: 使用者 MUST 能設定訓練使用的資料筆數（預設 2,000，下限 100，上限為資料集總筆數；超出範圍時顯示提示並拒絕開始）、訓練回合數、學習率與 LoRA 相關參數，且各參數有預設值與可接受範圍，預設值 MUST 能在 12GB 顯示卡上完成訓練
- **FR-010**: 系統 MUST 使用低位元量化的 QLoRA 方式訓練，使整個流程的顯示記憶體用量不超過 12GB
- **FR-011**: 系統 MUST 在訓練期間持續顯示回合、步數進度、損失值與預估剩餘時間，並將完整日誌寫入本機檔案
- **FR-012**: 系統 MUST 在訓練期間鎖定下載、模型選擇、微調模型刪除，以及所有推論與評測操作（避免搶用顯示記憶體）；終止訓練前 MUST 顯示警告並要求確認
- **FR-013**: 系統 MUST 在訓練過程定期保存檢查點，並支援中斷後從最近檢查點繼續
- **FR-014**: 訓練成功完成時，系統 MUST 自動保存微調成果，並將其登錄到「微調模型」下拉選單
- **FR-015**: 「用微調模型推論」按鈕 MUST 在沒有可用微調模型時維持不可用（灰色），並 MUST 在登錄成功後自動變為可用
- **FR-016**: 使用者 MUST 能選取微調模型並進行推論，且能將同一問題的微調前後回答並排對照
- **FR-016a**: 系統 MUST 提供選配的「執行題庫評測」功能：以內建小型推理題庫（每題附標準答案）分別對基底模型與所選微調模型作答，自動比對最終答案並顯示兩者答對率；使用者不執行評測時不影響其他功能
- **FR-016b**: 使用者 MUST 能刪除所選微調模型：刪除前顯示確認，確認後移除其成品檔案並從下拉選單消失；微調模型名稱由系統依建立時間自動產生，不提供改名；刪除後若已無微調模型，「用微調模型推論」按鈕 MUST 恢復灰色
- **FR-017**: 微調模型的登錄資訊 MUST 在應用程式重啟後保留，並在啟動時移除成品已不存在的項目
- **FR-017a**: 系統 MUST 僅支援公開可下載的模型與資料集，內建推薦項目皆須為公開項目；使用者手動輸入需登入或授權才能下載的項目時，系統 MUST 顯示說明「此項目需授權，本應用程式不支援」，且 MUST NOT 提供輸入存取權杖的介面
- **FR-018**: 系統 MUST 對常見失敗（記憶體不足、網路中斷、空間不足、模型不存在、資料集格式不符）顯示使用者看得懂的訊息與下一步建議
- **FR-019**: 所有介面文字 MUST 使用繁體中文（台灣用語）
- **FR-020**: 整個專案 MUST 可在 Ubuntu Linux 本機以隔離的虛擬環境安裝與啟動，且 MUST 附有從零開始的安裝與啟動說明

### Key Entities *(include if feature involves data)*

- **硬體資訊**: 目前顯示卡名稱、總記憶體、可用記憶體；用於篩選推薦模型
- **基底模型**: 模型代號、參數規模、預估訓練記憶體用量、下載狀態、本機位置
- **資料集**: 資料集代號、樣本數、欄位摘要、是否含思考過程、下載狀態
- **訓練任務**: 使用的基底模型與資料集、參數設定、狀態（等待／進行中／完成／失敗／已終止）、目前進度、損失值紀錄、日誌檔位置、檢查點
- **微調模型**: 來源訓練任務、對應基底模型、建立時間、成品位置、是否可用
- **推論紀錄**: 使用的模型（基底或微調）、輸入問題、生成參數、輸出內容、時間，用於前後對照
- **評測結果**: 評測的模型、題庫題數、答對題數、答對率、執行時間；基底與微調模型各一筆，供比較

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者在 12GB 顯示卡上，無需任何手動下載或指定資料夾，即可完成「選模型 → 選資料集 → 下載」，且從開啟網頁到兩者就緒的人工操作不超過 5 個步驟
- **SC-002**: 在 12GB 顯示卡上，以預設參數與小樣本資料集（1,000–5,000 筆）完成一次完整訓練的成功率達 100%（連續 3 次嘗試）且過程無記憶體不足失敗
- **SC-003**: 訓練期間畫面的進度與日誌至少每 10 秒更新一次，使用者不需重新整理頁面
- **SC-004**: 訓練完成後 5 秒內，微調模型出現在下拉選單且推論按鈕變為可用
- **SC-005**: 使用者執行題庫評測時，對同一組至少 10 題的小型推理題庫，微調後的答對率高於未微調基準（正向提升），且評測結果在 10 分鐘內顯示
- **SC-006**: 第二次啟動應用程式時，已下載的模型與資料集 100% 直接重用，不重複下載
- **SC-007**: 90% 的常見失敗情境（記憶體不足、網路中斷、空間不足）顯示的訊息，使用者無需查閱日誌即可知道下一步該做什麼
- **SC-008**: 全新環境依文件說明操作，可在 30 分鐘內（不含下載時間）完成安裝並看到網頁畫面

## Assumptions

- 使用者機器為 Ubuntu Linux，配備單張 12GB 顯示卡（RTX 3080 Ti），僅單機單使用者使用，不需登入與權限管理
- 訓練與推論皆在本機執行，不上傳使用者資料；只從公開的 Hugging Face 取得模型與資料集，不處理任何存取權杖或帳號登入
- 基底模型限定為 7B–8B 規模的蒸餾 thinking／reasoning 模型；推薦清單為內建固定清單，依專案規範（OpenR1-Distill-7B、DeepSeek-R1-Distill-Llama-8B、Qwen 系列），新增模型需更新清單；其他模型僅能由使用者手動輸入代號
- 訓練資料筆數由使用者自訂，預設以小樣本（約 2,000 筆）示範流程，確認損失下降後再自行擴大；筆數以外不提供複雜的資料篩選或處理
- 使用者指定的技術約束：Gradio 網頁、QLoRA、Unsloth、uv 與虛擬環境隔離；這些屬於既定限制，並非本規格要討論的選項
- 「最合適」的模型以「預估訓練記憶體用量不超過可用記憶體」為主要判斷標準，其次參考推理能力與下載大小
- 使用者回答的四個疑問（資料來源、基底模型、是否使用 QLoRA、如何展現結果）以文件形式於規劃階段提供結論：資料來源為公開推理資料集、基底模型為 7B–8B 蒸餾推理模型、使用 QLoRA、以微調前後並排對照呈現結果
- 非目標：多機訓練、雲端部署、完整評測平台、線上 API 服務；OpenAI 相容推論端點為選配，不在本次範圍
